## 1. Условие задачи (вариант 25, кратко)
В библиотеке необходимо восстановить каталог книг. Помещение содержит `M` рядов, в каждом ряду `N` шкафов, в каждом шкафу `K` книг. Каждая книга имеет “название” (в реализации — целое число `title`). Перед запуском приложения книги случайно размещаются по шкафам.

Требуется создать многопроцессное приложение, формирующее общий **отсортированный** каталог по информации от студентов, проверяющих местоположение книг. При решении использовать метод **«портфель задач»**: отдельная задача — составление каталога **одним студентом для одного ряда**. При добавлении данных в уже заполняемый каталог необходимо корректно учитывать, что каталог остаётся упорядоченным.

Каталог содержит строки вида: `(title, row, shelf, pos)`.

---

## 2. Сценарий, процессы и взаимодействие (требование №3)
**Сущности:**
- *Книга* — идентификатор `title` и позиция `(row, shelf, pos)`.
- *Ряд* — набор шкафов с книгами, является единицей работы.
- *Каталог* — общий список книг, отсортированный по `title`.

**Процессы:**
- **Init-процесс (`inventory_init`)** — создаёт общие ресурсы (shared memory и семафоры), случайно размещает книги, запускает/ожидает выполнения системы и выводит итоговый каталог.
- **Студент-процесс (`worker`)** — берёт задачу из портфеля (следующий ряд), формирует локальный список книг ряда, сортирует, затем сливает с общим каталогом.
- **Наблюдатель (`observer`)** — получает сообщения от студентов о ходе работы и выводит в свою консоль. Для оценки 10/10 допускается несколько наблюдателей.

**Портфель задач:**
- В разделяемой памяти хранится `next_row` — индекс следующего невыданного ряда.
- Студент атомарно берёт `row = next_row`, увеличивает `next_row`, после чего обрабатывает этот ряд.
- Завершение: когда `next_row >= M`, задач больше нет, процесс завершает работу.

## 3. Реализованные программы и соответствие уровням оценки
Реализованы 4 программы:

1) **`inventory_v1` (4–6 баллов)**  
   - Один родительский процесс → создаёт библиотеку и **fork()**’ает `P` дочерних процессов.  
   - Синхронизация: **неименованные POSIX семафоры** `sem_t` в shared memory (`pshared=1`).  
   - Обмен данными: POSIX shared memory.

2) **`inventory_init` + `worker` (7–8 баллов)**  
   - Процессы запускаются независимо в разных терминалах.  
   - Синхронизация: **именованные POSIX семафоры** (`sem_open`).  
   - Обмен данными: **POSIX shared memory** (`shm_open`, `mmap`).

3) **`observer` (9 баллов)**  
   - Добавлен независимый процесс-наблюдатель.  
   - Получает сообщения через **POSIX message queue** (`mq_open`, `mq_receive`).

4) **Несколько `observer` (10 баллов)**  
   - Каждый наблюдатель создаёт собственную очередь `/inv_obs_<pid>` и регистрирует её имя в shared memory.  
   - Студенты выполняют **broadcast**: отправляют каждое сообщение всем зарегистрированным очередям.  
   - Наблюдатели могут подключаться произвольно (в пределах `MAX_OBSERVERS`).

---

## 4. Данные и структуры (shared memory)
В shared memory хранится:
- `book_at_pos[M][N][K]` — фактическое размещение книг,
- `next_row` — портфель задач,
- `rows_done`, `catalog_count` — прогресс,
- `catalog[]` — общий отсортированный каталог,
- `observer_queues[]`, `observers_count` — список очередей наблюдателей.

Каталог поддерживается **отсортированным**: каждый студент сортирует свой ряд локально и затем выполняет слияние (merge) с глобальным каталогом.

---

## 5. Синхронизация (семафоры) и отсутствие гонок
Используются два семафора (в программах на 7–10 баллов):
- `SEM_PORTFOLIO` — защищает `next_row` (выдача задач).
- `SEM_CATALOG` — защищает общий каталог и список наблюдателей.

Это гарантирует:
- один ряд обрабатывается только одним студентом,
- каталог не повреждается при параллельных слияниях,
- регистрация/удаление наблюдателей потокобезопасна.

---

## 6. Завершение программ и очистка ресурсов (требования №4 и №5)
**Корректное завершение по сигналу:**  
- `inventory_init` обрабатывает `SIGINT` (Ctrl+C) и удаляет ресурсы.  
- `observer` обрабатывает `SIGINT` и:
  - удаляет своё имя из списка наблюдателей,
  - удаляет свою очередь сообщений `/inv_obs_<pid>`.

**Очистка ресурсов по завершению:**  
- `inventory_init` удаляет:
  - shared memory: `shm_unlink(SHM_NAME)`,
  - семафоры: `sem_unlink(SEM_PORTFOLIO_NAME)` и `sem_unlink(SEM_CATALOG_NAME)`.
- `observer` удаляет собственную `mqueue`.

*(Если процесс был принудительно убит, допускается ручная очистка или повторный запуск `inventory_init`, который выполняет `shm_unlink/sem_unlink` перед созданием.)*

## 7. Сборка в Linux/Ubuntu (CLion / WSL) (требование про Linux)
Зависимости:
```bash
sudo apt update
sudo apt install -y build-essential cmake ninja-build
```

Сборка (Ninja):
```bash
cmake -S . -B cmake-build-wsl -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build cmake-build-wsl -j
```

Проверка, что бинарники Linux (ELF):

```bash
file cmake-build-wsl/observer
```

## 8. Способы запуска (требование №6 и №7)

### 8.1 Программа 1 (4–6 баллов)
```bash
./cmake-build-wsl/inventory_v1 M N K P
# пример:
./cmake-build-wsl/inventory_v1 4 3 5 3
```

### 8.2 Программы 7–10 баллов (правильный порядок запуска)
Открыть 3 терминала.

**Терминал A (инициализация):**
```bash
./cmake-build-wsl/inventory_init 4 3 5
```

**Терминал B (один или несколько наблюдателей):**
```bash
./cmake-build-wsl/observer
# при необходимости в другом терминале ещё один:
./cmake-build-wsl/observer
```

**Терминал C (студенты параллельно):**
```bash
./cmake-build-wsl/worker 1 & ./cmake-build-wsl/worker 2 & ./cmake-build-wsl/worker 3 & wait
```

Параметры `M, N, K` задаются аргументами командной строки (`inventory_init`, `inventory_v1`), а число студентов в варианте 7–10 баллов задаётся фактом запуска произвольного количества процессов `worker`.

## 9. Результаты работы (требование №8)
В ходе работы:
- студенты выводят сообщения о получении и завершении обработки рядов,
- наблюдатель(и) печатают полученные сообщения,
- `inventory_init` выводит индикатор прогресса `rows_done` и итоговый отсортированный каталог.

### Пример фрагмента вывода (пример)
```
[OBSERVER] [WORKER 1] got row 0
[OBSERVER] [WORKER 2] got row 1
[OBSERVER] [WORKER 1] finished row 0
[OBSERVER] [WORKER 3] got row 2
...
[INIT] progress: rows_done=4/4 catalog=60/60
[INIT] FINAL CATALOG (60 entries)
book=   1  row= ...
...
```

## 10. Вывод
Реализовано многопроцессное приложение с портфелем задач для инвентаризации библиотеки. Поддержаны:
- POSIX shared memory,
- POSIX semaphores (неименованные и именованные),
- наблюдатель через POSIX message queues,
- подключение нескольких наблюдателей (broadcast).
Каталог формируется корректно и остаётся отсортированным по названию книги.
